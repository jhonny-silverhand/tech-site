# Technical Interview Prep in 30 Days: A Realistic Plan

You have a job, 90 minutes a day, and an interview in a month. Forget "grind 500 LeetCode problems." This plan targets what interview loops actually test — with rest days built in.

## The math of 30 days

90 min × 26 days ≈ 39 hours. Allocation: **50% DSA patterns, 25% system design (or domain depth), 15% behavioral, 10% mock interviews.** Patterns beat problem counts: 8 patterns cover ~80% of DSA questions asked at product companies.

## Week 1: Foundations + patterns 1–3

- **Day 1–2:** Big-O refresher + arrays/hashing (Two Sum, Contains Duplicate, Valid Anagram).
- **Day 3–4:** Two pointers + sliding window (3Sum, Longest Substring Without Repeating Characters).
- **Day 5–6:** Stack + binary search (Valid Parentheses, Search in Rotated Array).
- **Day 7:** Rest. Seriously — consolidation happens during rest.

Rule: 3 problems max per day. For each: solve → study the editorial → re-solve from memory next morning.

## Week 2: Patterns 4–6 + behavioral bank

- **Day 8–10:** Trees & graphs (Invert Tree, Level Order, Number of Islands, Clone Graph). BFS/DFS templates handle 70% of graph questions.
- **Day 11–12:** Heaps + intervals (Kth Largest, Merge Intervals).
- **Day 13:** Behavioral stories — write 6 STAR stories (conflict, leadership, failure, ownership, ambiguity, collaboration). Interviewers remember stories, not adjectives.
- **Day 14:** Rest.

## Week 3: System design + weak spots

- **Day 15–17:** System design framework: requirements → estimates → API → data model → scale (URL shortener, rate limiter, feed). Practice drawing and talking simultaneously.
- **Day 18–20:** Redo every problem you failed in weeks 1–2. This "failure list" session has the highest ROI of the whole plan.
- **Day 21:** Rest.

## Week 4: Mocks + taper

- **Day 22–24:** Timed mocks (45 min coding + 15 min review). Use a friend, a paid mock, or record yourself — talking while coding is a separate skill.
- **Day 25–27:** Company-specific prep: recent questions, stack-specific depth (React rendering, JVM GC, whatever the JD names).
- **Day 28–30:** Taper. Light revision, sleep 8 hours, exercise. Cramming the night before measurably hurts whiteboard performance.

## The pattern checklist

| Pattern | Signature problems |
|---|---|
| Sliding window | Longest substring, min window |
| Two pointers | 3Sum, container with most water |
| Fast/slow pointers | Cycle detection |
| Intervals | Merge, meeting rooms |
| BFS/DFS | Islands, clone graph, course schedule |
| Heap | Kth largest, top K frequent |
| DP (1D first) | Climbing stairs, house robber |
| Backtracking | Subsets, permutations |

## Key takeaways

- Patterns > problem count; 8 patterns cover most interviews.
- Re-solve failures — that session has the highest ROI.
- Mocks train talking-while-coding, a separate skill.
- Taper and sleep in the final 3 days.
