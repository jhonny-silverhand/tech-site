## Gotchas (ranked by how often they bite)

1. **Never share `.next` between dev and build.** Symptoms: `vendor-chunks/@supabase.js`, `5611.js`, `SegmentViewNode` manifest errors, random 500s in prod. `npm run dev` deletes `.next` on start; keep that behavior. Don't run two dev servers on the same dir/ports (3000/3003 conflicts seen historically).
2. **Restart dev after editing `.env.local`** — Next.js bakes env at boot. Applies to Vercel too: redeploy after changing dashboard env vars.
3. **Admin login 401** — `ADMIN_PASSWORD_HASH_B64` is empty or malformed. Generate: `npm run hash-password -- "password"` and paste the base64 exactly. It is base64-encoded because raw bcrypt hashes contain `$` that `.env` parsers silently corrupt.
4. **Admin dev credentials on record: `admin@techsite.com` / `admin123`** — rotate before trusting any deployment (also in Vercel env).
5. **Gemini 429/503 or 10–25 s product pages** — expected on the shared free tier. The router chain (`3.8 → 3.7 → 3.6`, 3 s gaps) then Groq (`GROQ_API_KEY`) handles outages; `/shopping` shows a heavy-load notice; compare has a loading skeleton. Check `GEMINI_API_KEY` first if *everything* AI returns 503 ("AI not configured").
6. **`featured` schema-cache error (OPEN BUG)** — "Could not find the 'featured' column of 'posts' in the schema cache". The column is in `website/supabase/schema.sql` (line 57) and a live REST probe returned it fine; suspicion is a stale PostgREST schema cache or a query against the wrong table/project. Next steps: diff schema vs live DB columns, run `NOTIFY pgrst, 'reload schema';` (or Supabase dashboard → restart), then re-test. Not yet resolved — don't "fix" by removing the column from queries.
7. **Supabase confirmation/reset emails linking to `localhost`** — set Supabase → Authentication → URL Configuration → Site URL to the real domain, and add **both** the production URL and `http://localhost:3000` to Redirect URLs (allowlist, not a replacement).
8. **Supabase keys are project-bound** — never copy keys between projects (the old project `kgflqrpdcaxccvuxyhff` keys will not work on `pploiphhwdmerwonqrct`). `SUPABASE_SERVICE_ROLE_KEY` must never be `NEXT_PUBLIC_` or committed.
9. **Dark-mode trap: `bg-ink` flips to a light color in dark mode** (it means "primary foreground"). Always-dark surfaces use `bg-void`. This bug shipped twice historically (secondary button, admin nav active state).
10. **Windows dev** — `/profile/@me` uses the URL-encoded folder `app/(main)/profile/%40me/` on purpose (Next.js + Windows filesystem); don't "normalize" it to `@me`.
11. **Wishlist button hidden on live-only products** — intentional (FK requires a catalog product id). Live AI products have no DB row.
12. **`website/public/version.json` is a build artifact** — regenerated by `scripts/gen-version.mjs` during `npm run build`. The committed copy (`1.0.0/unknown`) is stale; don't hand-edit it, don't treat it as the app version (use `package.json` / changelog).
13. **Covers** — explicit `cover_image_url` wins; otherwise curated per-niche pools (`lib/cover-pools.ts`); remote image hosts must be allowlisted in `website/next.config.mjs` (`**.cloudinary.net` needed the multi-level wildcard).
14. **Image uploads need the Supabase Storage bucket `post-images`** (public). Without it, pasting a URL still works.
15. **Security debt (2026-11-09):** Groq and Resend API keys were exposed in a past chat session — rotation pending. GitHub PAT used for pushing is embedded in the local git remote URL — never print `git remote -v` output publicly.

## FAQ

- **Which changelog is current?** `website/CHANGELOG.md` (1.x series, newest first). Root `CHANGELOG.md` is the legacy pre-rebuild log (v1.0–v4.3) — kept as history, with a status note on top.
- **Where's the real schema?** `website/supabase/schema.sql` (20 tables, idempotent — safe to re-run). `Guides/sql/schema.sql` is the legacy v4.0-era version.
- **How do products actually work?** Fetched live from Gemini at request time via `lib/ai-router.ts` → `lib/live-products.ts`. Prices are AI estimates (labeled), with Amazon.in/Flipkart **search** links. There is no offline catalog anymore.
- **Why does the site work without any env vars?** Dual data mode: every content function falls back to `content/seed-posts.ts` + `content/articles/*.md` when Supabase isn't configured.
- **What's in `archived/website-backup/`?** The frozen pre-rebuild snapshot (scraped-catalog era). Read-only history — don't build on it.
- **What is `website/temp.md`?** Not app documentation — a personal GitHub-profile README draft (Johnny Silverhand style). Flagged 2026-11-09; awaiting owner decision.
- **How do I verify a deploy?** Vercel Root Directory is `website`; after push, check the deployment, then `/admin/login` and an AI product page on the production URL.
- **Loopback checklist (used by past sessions):** `npx tsc --noEmit`, key pages return 200/307/404 correctly, console free of errors, admin + products APIs respond.
